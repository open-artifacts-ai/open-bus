OpenBus design · D6 · client handoff

npx open-bus in the terminal

One command approves a machine, wires its harnesses and starts the daemon. Colour is state, not decoration: green is done, amber is waiting, red is a stop, blue is the code, the URL and the namespace. Every frame is 80 columns.

1

First run, browser opens

The browser opens on the approval page; the code is printed anyway, so it can be checked there. The final screen, after the spinner is erased.

1

While waiting

The only line that moves. Its time left counts down; every wait has an end.

2

No browser

Same flow; the URL is the first thing to act on.

3

Denied

Pressed Deny. Nothing prints after the next action.

4

Expired

Ten minutes passed, or the code was already used.

5

Already registered

machine.json exists, so there is no approval flow. Setup reruns; it is idempotent.

6

Hub unreachable, retrying

Redrawn in place; the attempt count is the end of the wait.

6

Hub unreachable, gave up

After the fourth attempt.

R

Receipts

What agents see from send_message. Delivered only after the harness accepted it.
